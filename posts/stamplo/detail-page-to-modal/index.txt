## 상황

Stamplo 유저 사이드에는 브로셔 페이지 외에 행사 상세 정보를 보여주는 화면이 별도 페이지로 존재했다.
이게 들어가는게 약간 복잡했는데 우선 미션 페이지에서 브로셔 버튼을 클릭한 뒤 아래 있는 행사 상세 정보 버튼을 누르면 보이는 구조였다.
저런 구조로 있던 이유는 두 정보가 사실상 같은 성격이었기 때문이고, 브로셔는 행사 주최 입장에서 필수 업로드 부분이 아니다보니 브로셔가 없는 경우 부족한 정보를 주기위해 행사 상세 정보를 볼 수 있게 한 섹션이었기 때문이었다.

문제는 **1.(브로셔가 있는경우) 뒤로 가기를 한다면 보이는 브로셔 페이지를 굳이 저 버튼에 넣는 것**과 **2. 상세보기까지 가는 ux가 왼쪽 위 브로셔 버튼을 클릭해 아래 쪽에 있는 상세보기 버튼을 클릭한 뒤 나가는 버튼은 또 위 왼쪽에 있는 뒤로 가기를 클릭하는 것이 조잡하고 헷갈리는 것**이었다.
사실 이것에 대한 이슈는 새로 나온게 아니었다. 이 상세 페이지를 만들었을때부터 멘토와 같은 팀원에게도 들어왔고 1차 mvp 때도 들었던 의견이었다. 다만 다른 기능 추가 개발과 리팩토링이 우선되어서 뒤로 밀리다 운영 4일전에 이렇게 등장한 것이었다.

나는 반대하는 입장이었다. 단순히 페이지를 모달로 바꾸는 문제가 아니라 여러 페이지를 함께 고치고 케이스를 다시 맞춰야 하는, 사실상 새 개발에 가까웠기 때문이다. 게다가 상세 페이지는 이미 QA를 마친 기능이라, 구조를 바꾸면 그 검증을 처음부터 다시 해야 하기에 오픈을 앞둔 지금 바꾸는 것이 좋지않은 판단이었다.

그럼에도 내부 피드백과 바꾸는 것에 대한 메리트를 생각해 진행하는 쪽으로 협의되었고 마침 맡고 있던 작업이 끝나기도 해 상대적으로 널널한 내가 이 작업까지 이어받게 됐다.ㅜ

우선 정보를 확실하게 알리기 위해서 미션 페이지의 브로셔 버튼을 제거하고 행사정보 버튼을 만들었다.
또한 기존 페이지로 되어있던 상세 페이지를 모달로 바꾸고 클릭 시 바로 보이도록 수정했다.

모달로 바꾼 이유는 단순히 취향 문제가 아니라, 조금 더 근본적인 이유가 있는데 상세 정보는 사용자가 가려고 하는 목적지가 아니라, 지금 보고 있는 화면 위에 잠깐 얹히는 부가 정보에 가깝다.
따라서 별도 URL과 페이지 전환은 "여기가 새로운 목적지"라는 무게를 실리기 때문에, 이 가벼운 흐름에는 맞지 않아 모달로 아예 바꾸는 선택을 했다.

그래서 `app/(user)/event/[eventId]/detail/page.tsx`와 이를 채우던 `EventDetailClient.tsx`를 삭제하고, 같은 자리에서 열고 닫히는 `EventDetailModal.tsx`로 교체했다.

```
- app/(user)/event/[eventId]/detail/page.tsx       (삭제)
- components/user/event/EventDetailClient.tsx       (삭제)
+ components/user/event/EventDetailModal.tsx         (신규)
+ components/user/event/EventDetailModalSkeleton.tsx (신규)
+ components/user/event/EventDetailButton.tsx        (신규)
```

라우트 자체를 지웠기 때문에 상세 정보를 열어도 URL이 바뀌지 않고, 사용자는 브로슈어나 미션 화면의 맥락을 잃지 않은 채로 정보를 확인할 수 있게 된다.

데이터를 가져오는 방식도 페이지 시절과 달라졌다. 이전에는 페이지 자체가 진입 시점에 데이터를 로드했지만, 모달은 "열렸을 때만" 데이터가 필요하다. 그래서 TanStack Query의 `queryOptions` 팩토리로 쿼리를 정의해두고, 모달의 `isOpen` 상태를 그대로 `enabled` 조건에 연결했다.

```ts
// features/participant/events/participantEventQueries.ts
export const participantEventQueries = {
  all: () => ["participant", "event"] as const,
  detail: (eventId: number) =>
    queryOptions({
      queryKey: [...participantEventQueries.all(), "detail", eventId] as const,
      queryFn: () => fetchParticipantEvent(eventId),
      enabled: eventId > 0,
    }),
};
```

```tsx
// components/user/event/EventDetailModal.tsx
const { data: event } = useQuery({
  ...participantEventQueries.detail(Number(eventId)),
  enabled: isOpen,
  staleTime: 300_000,
});
```

모달이 닫힌 상태에서는 요청 자체가 나가지 않고, 한 번 연 뒤 5분 안에는 `staleTime`으로 캐시를 재사용해 같은 상세 정보를 다시 열 때 재요청하지 않는다. 페이지였다면 라우트 진입 자체가 요청 트리거였지만, 모달에서는 이 트리거를 직접 정의해야 한다.

## 각종 에러들

아무래도 여러 케이스를 대비 하고 개발에 임했지만 급하게 하다보니 이것 저것 에러가 발생했다.
PR을 올리니 팀원들이 열심히 찾아줘서 사전에 방지할 수 있었다. ~다들 고마워..~

> 뒤로가기가 안돼요

안드로이드에서 네이티브 뒤로가기 버튼을 누르면 모달이 닫혀야되는데 아예 이전 페이지인 브로셔 페이지로 가버리는 이슈가 발생했다.
pr 코멘트 그대로 기존에 있는 히스토리를 넣어주는 훅을 넣어 이슈를 해결했다.

**히스토리 훅**

```ts
// hooks/useModalHistoryBack.ts
export const useModalHistoryBack = (isOpen: boolean, onClose: () => void) => {
  useEffect(() => {
    if (!isOpen) return;

    // 모달이 열릴 때 현재 URL로 히스토리 엔트리 하나 추가
    history.pushState({ modal: true }, "");

    const handlePopState = () => onCloseRef.current();
    window.addEventListener("popstate", handlePopState);

    return () => {
      window.removeEventListener("popstate", handlePopState);
      // X 버튼 등으로 수동으로 닫힐 경우, 남았던 히스토리 엔트리를 정리
      if (history.state?.modal) history.back();
    };
  }, [isOpen]);
};
```

모달이 열리는 시점에 히스토리 엔트리를 하나 쌓아두고, `popstate`(뒤로가기) 이벤트가 오면 라우트 이동 대신 모달을 닫는 쪽으로 가로챈다.
모달을 열 때 `pushState`로 가짜 히스토리 한 칸을 쌓아두면, 뒤로가기는 그 칸을 소비하면서 `popstate`만 발생시키고 실제 페이지 이동은 일어나지 않는다.
반대로 X 버튼처럼 모달을 코드로 직접 닫을 때는 쌓아뒀던 히스토리가 그대로 남아있으면 안 되므로, `history.back()`으로 정리해 히스토리 스택을 원래 상태로 되돌린다.

> 모달을 열었을 때 스크롤이 안돼요.

콘텐츠가 길어지는 경우 모달 하단이 화면 밖으로 잘리고 스크롤도 되지 않아, 일부 정보에 아예 접근할 수 없는 상태가 됐다.

**수정 전**

```tsx
// components/user/event/EventDetailModal.tsx (수정 전)
<DialogPrimitive.Content
  className={cn(
    "fixed top-14 left-1/2 -translate-x-1/2 z-50 w-[calc(100%-3rem)] max-w-sm max-h-[85vh] rounded-[24px] bg-gomin-primary-100 flex flex-col overflow-hidden shadow-xl",
    "animate-slide-down outline-none",
  )}
>
  <DialogClose asChild>{/* 닫기 버튼 */}</DialogClose>

  <div className="overflow-y-auto scrollbar-hide">
    {event ? (
      <div className="bg-gomin-primary-100 pt-13 px-4 pb-6 flex flex-col gap-3">
        {/* 행사명, 일정, 장소, 주최자, 비고 카드들 */}
      </div>
    ) : (
      <EventDetailModalSkeleton />
    )}
  </div>
</DialogPrimitive.Content>
```

바깥 컨테이너는 `max-h-[85vh]`(최대 높이 제한)에 `flex flex-col`이었고, 콘텐츠를 감싼 내부 `div`에만 `overflow-y-auto`를 줬다.
그런데 이 내부 `div`에 명시적 높이 제약이 없다 보니, `flex` 자식 기본값인 `min-height: auto` 때문에 부모의 `max-h-[85vh]` 제한을 무시하고 콘텐츠 크기만큼 늘어나 버렸다.
결국 바깥의 `overflow-hidden`이 넘친 부분을 그냥 잘라내면서, 정보 일부가 보이지도 스크롤되지도 않는 상태가 됐다.

**수정 후**

```tsx
// components/user/event/EventDetailModal.tsx
<DialogPrimitive.Content
  className={cn(
    "fixed top-14 left-1/2 -translate-x-1/2 z-50 w-[calc(100%-3rem)] max-w-sm h-[70vh] rounded-[24px] bg-gomin-primary-100 overflow-hidden shadow-xl outline-none",
    "animate-slide-down",
  )}
>
  <DialogClose asChild>{/* 닫기 버튼 */}</DialogClose>

  <div className="h-full overflow-y-auto scrollbar-hide">
    {event ? (
      <EventDetailContent event={event} />
    ) : (
      <EventDetailModalSkeleton />
    )}
  </div>
</DialogPrimitive.Content>
```

바깥 컨테이너를 유동적인 `max-h-[85vh]` 대신 고정 높이 `h-[70vh]`로 바꾸고 `flex flex-col`을 제거했다. 그리고 내부 `div`에 `h-full`을 명시해 부모의 고정 높이를 그대로 상속받게 했다. `max-height`는 콘텐츠가 그보다 작으면 줄어드는 유동값이라 스크롤 컨테이너의 기준으로 쓰기 어려웠던 것이고, 부모가 고정 높이를 갖고 자식이 그 높이를 `h-full`로 명시적으로 받아야 `overflow-y-auto`가 제대로 동작한다.

그 외 이 페이지와 상관없는 버그들도 발견되고 고질적인 색 주입 관련 버그(FOUC 버그다)들도 터졌지만 순조롭게 해결했다.
