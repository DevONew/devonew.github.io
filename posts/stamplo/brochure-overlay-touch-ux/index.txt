## 개요

원래는 브로셔 페이지 글을 한번에 포스팅 할려고 했었는데 오버레이 관련 부분이 길어지면서 분리 하게 되었다.  
브로셔 페이지를 작업하면서 있던 배포하고 나서 모바일로 확인한 버그, 에러에 대해 해결한 과정들을 정리한다.

## 배포 후 QA에서 잡은 UX를 해치는 문제들

물론 PC에서 개발할 때 어느정도 고려하고 개발을 하는데 배포 후(프리뷰 혹은 개발 서버) 모바일에서 확인을 할 때 이슈가 꽤 발생 되었다.

### 오버레이 뒤 배경 스크롤

오버레이 뒤 배경이 스크롤이 되는 이슈다.
아...기본 중에 기본인데 [뒤 포스팅에 나올 이슈](/posts/stamplo/brochure-overlay-ssr/)를 생각하다 보니 놓친 이슈다.

```tsx
// components/user/brochure/BrochureGuideOverlay.tsx
useEffect(() => {
  if (visible) {
    document.body.style.overflow = "hidden";
  }
  return () => {
    document.body.style.overflow = "";
  };
}, [visible]);
```

오버레이가 보이는 동안에만 body의 overflow를 hidden으로 바꿔서, 뒤에 깔린 페이지가 함께 스크롤되지 않도록 막았다.

### 인앱 브라우저에서 오버레이 뒤 배경 스크롤

이건 우연히 발견한건데 카카오톡에서 링크를 공유하다가 카카오 내 브라우저에서 브로셔를 열었더니 거기는 또 스크롤이 되는 것을 확인했다;
찾아보니 꽤 흥미로운 이슈였는데 **카카오톡 인앱 브라우저에서는 overflow: hidden이 먹히지 않는다는 것이었다.**
정확한 원인이 공식적으로 밝혀진 건 아니지만, 개인적으로 추정하기로는, 인앱 웹뷰가 HTML의 CSS 레이어보다 더 아래(네이티브) 단에서 스크롤을 직접 처리하기 때문이 아닐까 싶다.
아니면 카카오는 커스텀 웹뷰를 쓰다보니 거기에 있는 속성과 충돌나서 안되는 걸수도 있을거 같다.

```tsx
// components/user/brochure/BrochureGuideOverlay.tsx
useEffect(() => {
  const prevent = (e: TouchEvent) => e.preventDefault();
  if (visible) {
    document.addEventListener("touchmove", prevent, { passive: false });
  }
  return () => {
    document.removeEventListener("touchmove", prevent);
  };
}, [visible]);
```

오버레이가 떠 있는 동안에는 touchmove 이벤트를 직접 가로채 preventDefault()로 취소해서, CSS(overflow: hidden)가 통하지 않는 인앱 브라우저에서도 뒤 배경 스크롤을 막았다.

#### 출처

- [카카오톡 커스텀 웹뷰 (리버스 엔지니어링 분석 문서)](https://github.com/stulle123/kakaotalk_analysis/blob/main/doc/WEBVIEW.md)
- [인앱 브라우저에서 overflow 속성이 안 먹힌다는 문의 (카카오 데브톡)](https://devtalk.kakao.com/t/overflow/144209)
  (카카오 인앱 브라우저에 생각보다 오류가 많나보다..포럼 글이 꽤나 많이 있다.)

### 슬라이더 터치 스크롤 충돌

브로셔 페이지에는 브로셔를 전체 보기 위한 위아래 스크롤, 넘기기 위한 좌우 탭(스와이프X)가 있다.
브로셔 슬라이더 위에서 아래로 슬라이드를 하면 스크롤이 버벅이면서 내려가게 되는데 원인은 슬라이더 좌우 절반을 덮은 이전/다음 버튼에 있었다.
이 버튼들은 탭으로 페이지를 넘기는 클릭 핸들러를 갖고 있으면서 동시에 터치 방향 제약이 없는 상태(touch-action: auto)다.
그래서 사용자가 버튼 위에서 위아래로 스와이프해도 브라우저가 "이게 스크롤로 이어지는 움직임인지" 판단할 때까지 기다리느라, 스크롤이 곧바로 시작되지 못하고 지연이 생겼다.

```ts
// components/user/brochure/BrochureSlider.tsx
<button
  className="absolute left-0 top-0 w-1/2 h-full z-10 touch-pan-y"
  onClick={onPrev}
  aria-label="이전 페이지"
/>
```

touch-action: pan-y(touch-pan-y)로 세로 스와이프만 즉시 스크롤 처리되게 했다. 좌우 넘김은 탭으로 작동해 영향 없다.

여기는 브로셔 마지막장에 갈 경우 미션 페이지로 넘어가는 버튼이 나오는데 UI·UX 완성도를 위해 미션목록 페이지의 버튼과 같은 컴포넌트로 교체 했다.

#### 교체 전 — page.tsx에서 ThemedButton을 직접 사용

```ts
// app/(user)/event/[eventId]/brochure/page.tsx
{!fromMission && isLastPage && (
  <div className="mt-6 w-full max-w-76 px-4 flex justify-center animate-in fade-in slide-in-from-bottom-2 duration-300">
    <ThemedButton
      className="w-full"
      onClick={() => router.push(`/event/${eventId}/mission`)}
    >
      스탬프 투어 시작하기
    </ThemedButton>
  </div>
)}
```

#### 교체 후 — 미션 목록 페이지에서 쓰던 FloatingActionButton 재사용

```ts
// app/(user)/event/[eventId]/brochure/page.tsx
{!fromMission && isLastPage && (
  <FloatingActionButton
    label="스탬프 투어 시작하기"
    onClick={() => router.push(`/event/${eventId}/mission`)}
  />
)}
```

#### 재사용을 가능하게 한 컴포넌트 쪽 변경 — label prop 추가

```ts
// components/user/mission/FloatingActionButton.tsx
interface FloatingActionButtonProps {
  isAllCompleted?: boolean;
  onClick: () => void;
  label?: string;
}

{label ? (
  <span>{label}</span>
) : !isAllCompleted ? (
  <>
    <ScanLine className="w-5 h-5 stroke-[2.5]" />
    <span>QR 체크하기</span>
  </>
) : (
  ...
)}
```

ThemedButton 컴포넌트에서 FloatingActionButton로 교체.
label prop을 추가해, 기존 "QR 체크하기" 문구 대신 "스탬프 투어 시작하기" 같은 커스텀 문구를 넘길 수 있도록 확장했다.
